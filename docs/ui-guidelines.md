# UI Guidelines

## 目的

Tab Saver の UI は、見た目の演出よりも「保存済みタブを短時間で見つけて操作できること」を優先する。

特に `newtab` ダッシュボードでは、1 画面内で確認できる件数を増やし、検索、並び替え、復元までを最短導線で完結させる。

## 基本方針

- 一覧性を最優先にする
- 主要操作は一覧の近くに置く
- 装飾より情報密度を優先する
- 余白は広げすぎず、視線移動を短く保つ
- モバイルや軽量 UI では描画負荷も同時に抑える

## レイアウト原則

### 1. 一覧をできるだけ上に出す

- 大きなヒーローや説明文でファーストビューを消費しない
- 上部には状態把握に必要な最小限のサマリーだけを置く
- 初回表示時に、保存済みグループ一覧がすぐ見え始める構成を維持する

### 2. 主従を明確にする

- 主役は保存済みグループ一覧
- 設定、認証、保存フォームは補助カラムまたは折りたたみ領域に置く
- ユーザーの主目的が「探す」「開く」「復元する」であることを崩さない

### 3. 横幅を情報量に使う

- デスクトップでは一覧領域を広く確保する
- 補助パネルは必要最小限の幅に抑える
- 広い画面ではカードを大きくするより、一覧の可視件数増加を優先する

## コンポーネント原則

### サマリーカード

- 数値確認に必要な情報だけを表示する
- カードの高さは低めに保ち、上部の占有面積を増やしすぎない
- 補足説明は短くし、長文カードは追加しない

### グループカード

- 1 グループあたりの縦幅をできるだけ小さくする
- タイトル、日時、タブ数、端末名を短い視線移動で読めるように並べる
- 操作ボタンはカード内に収めつつ、一覧の可読性を壊さないサイズにする

### タブ行

- 1 行の高さを抑える
- タイトルとドメインを優先表示する
- URL 全文よりもホスト名を優先する
- 状態表示は小さなバッジで済ませる

### 検索とフィルタ

- 一覧の直上に置く
- 頻繁に使う順に、検索、並び順、状態フィルタを配置する
- フィルタ操作後の件数がすぐわかるよう、結果メタ情報を近くに表示する

## スタイル原則

### 余白

- パネル内余白は広げすぎない
- カード間隔、ボタン間隔、フォーム間隔は詰め気味を基本にする
- 情報が窮屈に見えない最小限の余白を目安にする

### タイポグラフィ

- 本文や補助情報はやや小さめでよい
- タイトルだけを必要以上に大きくしない
- ラベル、メタ情報、状態表示は階層差が伝わる範囲でコンパクトにする

### 装飾

- グラデーションやガラス風表現は使ってよいが、情報密度を下げない範囲に留める
- 装飾用カードや長文導線は、一覧の初期表示面積を圧迫するなら避ける

## レスポンシブ原則

- 狭い画面では 1 カラム化を優先する
- ただし、モバイルでも一覧の密度は極端に落とさない
- 軽量 UI ではアニメーション、影、描画コストの高い表現を減らす
- 折りたたみや段階表示を使い、必要な情報だけを展開できるようにする

## 今後の判断基準

UI 変更を検討するときは、以下を確認する。

1. この変更で、1 画面内に見えるグループ数またはタブ数は増えるか
2. 一覧の開始位置は下がっていないか
3. 検索、並び替え、復元までの操作回数は増えていないか
4. 補助情報が主目的の一覧を邪魔していないか
5. モバイルや Android Firefox の軽量表示でも破綻しないか

上の問いに反する場合は、見た目の改善だけで採用しない。
